# 飞书消息发送转发与群聊 Agent 路由平台

这是一个空配置的本地消息桥接工程：接收群内消息、按路由调用 Agent，并通过飞书自建应用发送结果。构建包不含任何真实群、凭据、会话或发送记录；所有渠道默认关闭。

这里的“Agent 路由”是指把群聊请求交给某个 Agent，不是 Windows 定时任务。招聘采集、评分和晚间日报调度位于相邻的 `招聘智能体/recruitment-agent`。

## 首次配置

1. 复制 `.env.example` 为 `.env`，填写你自己的飞书应用凭据和测试群 ID。
2. 在 `channels.config.json` 中把 `allowed_chat_ids` 的示例值替换为自己的群 ID。
3. 在 `routes.config.json` 中替换相同的示例群 ID。
4. 完成飞书应用权限、事件订阅和机器人入群后，才将对应 `enabled` 改为 `true`。
5. 如需岗位话术，先在相邻招聘项目创建自己的候选人画像与岗位索引。
6. 如果使用 HTTP 事件回调，必须填写 `FEISHU_EVENT_VERIFY_TOKEN`；启用飞书 Encrypt Key 时同时填写 `FEISHU_EVENT_ENCRYPT_KEY`。程序会校验 token、签名、时间戳和重复请求。这里保护的是“别人伪造一条飞书入站消息来触发 Agent”的风险，不是说别人知道配置后就能直接替你发飞书消息。

分享包当前对 HTTP 加密正文采取安全失败：验签后若收到 `encrypt` 密文会明确拒绝，避免把密文误当普通事件。需要加密事件正文时，应接入飞书官方 SDK 的解密处理；本机使用长连接时由 SDK 完成连接认证，不经过该 HTTP 回调。

## 目录与命令

- `src/`：渠道、路由、发送与会话逻辑。
- `tests/`：仅使用虚构群聊和示例岗位的回归测试。
- `data/`、`logs/`：首次运行时自动创建的本地状态与日志，不应上传。

```powershell
node .\tests\run_tests.js
node .\src\cli\simulate_event.js .\tests\fixtures\feishu_greeting_event.json --force-enabled --no-send
node .\src\cli\start_feishu_long_connection.js
```

最后一条命令会连接你配置的飞书应用；未完成配置前不要运行。发送侧会使用三次重试、幂等键和本地审计状态；不应把 `.env`、`data/` 或 `logs/` 加入分享包。

## 与招聘 Agent 的边界

消息平台不直接读取招聘项目的岗位索引、候选人画像或岗位库。群内出现 `A001`、`B001`、岗位链接、JD 文本或截图 OCR 文字时，消息平台只负责清洗消息、维护会话、路由到配置的 Agent，并把结果发回群里。

岗位编号解析、候选人匹配、AI/规则降级、打招呼话术，以及 BOSS/猎聘采集失败或部分成功的告警正文，均由相邻的 `招聘智能体/recruitment-agent` 负责。消息平台只负责凭据校验、幂等、重试、发送审计和送达状态记录。
