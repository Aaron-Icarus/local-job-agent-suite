# 岗位 JD 清洗 Skill（猎聘/BOSS 通用）

## 目标

从招聘平台详情页文本中区分：

- 岗位真实 JD；
- 岗位简要信息；
- 招聘方信息；
- 平台导航、按钮、广告、推荐岗位、安全提示、页脚。

**原始 JD 必须保留**；清洗结果单独保存，后续比对仍使用原始内容，阅读/评分使用清洗结果。

## 猎聘页面结构识别

### 1. 页面头部（丢弃）

例如：

```text
首页 职位 校园 海归 简历优化 关于猎聘 我要招人
你好，吴先生 邀请应聘 我的投递 我的收藏 猎聘APP 投诉建议
```

这些是平台导航/账户入口，不是岗位内容。

### 2. 岗位简要信息（提取）

例如：

```text
AI项目经理
30-45k
上海
10年以下
本科
招1人
10月28日更新
```

对应：

| 页面信息 | 字段 |
| --- | --- |
| 岗位名 | title |
| 30-45k | salary_text / salary_min_k / salary_max_k |
| 上海 | city |
| 10年以下 | experience |
| 本科 | degree |
| 招1人 | hc_count |
| 10月28日更新 | job_updated_at |

**岗位更新时间非常重要**：长期不更新的岗位可能已无效，不能因为“还开着”就当作新岗位。

### 3. 招聘方信息（提取）

例如：

```text
邵女士 1天前在线 已认证 猎头顾问 · 北京科锐国际人力资源股份有限公司上海分公司
```

对应：

- `recruiter_name`
- `recruiter_online`
- `recruiter_certified`
- `recruiter_type`（猎头/HR/招聘专员/顾问）
- `recruiter_company`

超过 7 天不在线：低置信度，日报不推。

**BOSS 渠道同样的字段**：

```text
黄女士 刚刚活跃 悉地 · 综合行政专员
```

提取为：

- `recruiter_name = 黄女士`
- `recruiter_online = 刚刚活跃`
- `recruiter_company = 悉地`
- `recruiter_title = 综合行政专员`
- `recruiter_type = 招聘方`

不要因为姓名不同、公司不同、职位不同就写成专用规则；只识别“姓名 + 活跃状态 + 公司 · 职位”的结构。

### 4. 系统功能（丢弃）

例如：

```text
聊一聊
收藏
微信分享扫码
举报
```

### 5. 真实 JD（保留）

从 `【职位描述】` / `职位描述` / `岗位职责` 开始，到：

```text
其他信息
语言要求
行业要求
```

之前的内容保留；保留原始换行、编号、段落。

### 6. 平台提示与推荐（丢弃）

从以下任一标记开始，到页面末尾全部丢弃：

```text
猎聘温馨提示
猜你喜欢
当前位置：
更新时间：      # 更新时间只提取字段，不写入 JD
相关推荐
更多职位推荐
```

尤其是“猜你喜欢/相关公司/热门城市/周边城市”里会出现**别的岗位**，绝不能混入当前 JD。

## 格式还原

清洗不是把 JD 压成一段。保留/恢复：

- `岗位定位`、`职责`、`任职要求`、`加分项`、`其他信息` 等标题前换行；
- 编号列表 `1.`、`2.`、`1-`、`2-` 每项单独一行；
- `•` / `·` 项目符号单独一行；
- 段落之间最多一个空行；
- 删除页面导航、按钮、广告、推荐，但不把正文重新改写成摘要。

## 猎聘/BOSS 共用字段

```text
title
salary_text
city / district
experience
degree
hc_count
job_updated_at
recruiter_name
recruiter_online
recruiter_certified
recruiter_type
recruiter_title
recruiter_company
jd_clean_text
```

## 示例：B023

```text
产品市场经理（工业软件 × AI Agent方向）(J10872)
20-40k·17薪
上海-闵行区
3-5年
本科
招1人
11月6日更新
龚女士 1天前在线 已认证 顾问 · 柏楚电子
职位介绍
岗位定位：...
职责
1. 市场洞察与行业分析...
2. 机会论证与辅助立项...
```

清洗后应保留 `岗位定位/职责/任职要求/加分项/其他信息` 的层级和编号，不应把导航、福利按钮、猜你喜欢一起保留。

## 输出字段

- `jd_clean_text`：清洗后的真实 JD；
- `job_updated_at`：岗位更新时间；
- `recruiter_*`：招聘方信息；
- `hc_count`：HC；
- 原始 `job_description` 保持不变；
- `jd_clean_version`：清洗规则版本。

## 清洗原则

1. 先保存原始文本，再清洗；清洗失败不能覆盖 raw；
2. 不做“摘要式改写”，尽量还原原始格式；
3. 只删除平台 UI/广告/推荐，不删除岗位职责、要求、加分项、其他信息；
4. 页面字段缺失时留空，不猜测；
5. 新规则上线后按版本回填历史岗位；
6. 快速比对使用原始内容 hash，展示/评分使用清洗文本。

## 校验

- [ ] 开头不是平台导航；
- [ ] 结尾不是“猜你喜欢/温馨提示/当前位置”；
- [ ] 没有其他岗位的标题/公司/薪资；
- [ ] 岗位名、薪资、城市、经验、学历、HC、更新时间能提取；
- [ ] 招聘方姓名、在线时间、认证、类型、公司能提取；
- [ ] JD 原始段落和编号保留。
