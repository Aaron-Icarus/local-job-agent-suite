# 岗位评分 Skill（通用版）

## 目标

对岗位做可解释评分，并明确哪些岗位适合进入当天日报。评分不是“谁分高就推”，还要看岗位是否真实、是否可联系、是否在有效期内。

## 输入

- 角色画像、目标岗位、目标城市、目标薪资；
- 岗位原始 JD（用于内容比对）；
- 清洗后的 JD（用于阅读/评分）；
- 岗位更新时间、招聘方在线时间、认证状态、HC；
- 岗位状态、是否重复、采集时间。

## 硬性判断

先排除：

- 已关闭、重复岗位；
- 明显不在目标城市且不可远程；
- 薪资上限低于用户底线；
- JD 为空或只有平台导航/推荐内容；
- 岗位更新超过 180 天且招聘方超过 7 天不在线；
- 招聘方超过 7 天不在线，且没有其他活跃信号：降为低置信度。

## 评分维度

| 维度 | 权重 | 说明 |
| --- | --- | --- |
| 岗位/职责匹配 | 35% | 目标岗位名、职责、行业方向 |
| 技能/经历匹配 | 25% | 技能关键词、项目、工具、成果 |
| 薪资匹配 | 12% | 与目标区间重叠程度 |
| 地点匹配 | 10% | 城市/区域/远程 |
| 招聘方可信度 | 10% | 认证、在线时间、招聘方类型 |
| 新鲜度/活跃度 | 8% | 岗位更新时间、采集时间、HC |

## 目标岗位解析

- 目标岗位可能写成多个方向，例如“AI项目经理和AI产品经理”“项目经理或者产品经理”；
- 必须按 `、，, / ; ； |` 以及“和/或/及/与/或者”拆分，并统一存成 `岗位A、岗位B`；
- 先用完整岗位词匹配，再从目标岗位和角色关键词本身推导岗位方向词；不要预设某个行业词表；
- 例如目标岗位“财务经理”可以推导“财务、经理”，目标岗位“AI项目经理”可以推导“AI、项目、经理”；这些词来自用户自己的目标/关键词，不是固定行业词；
- 不能把整句“项目经理或者产品经理”当成一个完整岗位词，否则所有岗位都会匹配失败；
- 目标岗位越具体，分数越有区分度；如果目标岗位只有“项目经理”，不要把某个行业岗位因为经历里的旧方向强行抬高。

## 本地基线 + AI 复核

评分分两层：

1. **本地确定性基线**：先按岗位事实、目标岗位、关键词、薪资、城市、活跃度算出基线分；
2. **AI 复核**：把岗位、角色画像、基线理由和本 Skill 交给已启用的 AI Provider，只允许在基线分上做有限微调（默认 ±8），不得改变薪资/城市/关闭/重复等硬条件，不得编造。

AI 返回失败、超时或没有可用 Provider 时，保留本地基线分，不把失败伪装成 AI 分数。

出现“所有岗位分数接近”时，先检查：

1. 角色的 `target_roles` 是否保存成了完整长句；
2. 角色关键词是否为空或全被过滤；
3. 目标城市/薪资是否解析失败；
4. 是否点击了“重新评分”（旧评分不会自动重算）。

## 置信度规则

- 招聘方 `刚刚在线/今日在线`：正常；
- `1–3 天前在线`：轻微降权；
- `4–7 天前在线`：明显降权；
- `7 天以上不在线`：低置信度，建议不进入日报；
- 岗位更新时间超过 90 天：降权；超过 180 天：默认不推；
- JD 清洗后不足 80 字：低置信度。

## 输出

```json
{
  "score": 0,
  "tier": "高/中/低",
  "reasons": ["..."],
  "risks": ["..."],
  "suitable_for_report": false
}
```

- `score` 0–100；
- 日报默认只收录当天评分且 `score >= 60`、非低置信度的岗位；
- 低置信度岗位即使分数高，也要在风险中标注“招聘方长期不在线/岗位过旧”。

## 原则

- 只使用岗位事实和角色画像，不编造；
- 清洗前后都保留：原始 JD 用于比对，清洗后 JD 用于评分；
- 评分理由要能对应到 JD、薪资、地点、招聘方状态；
- 同一岗位对不同角色独立评分；
- 历史分数只用于展示，不覆盖本轮事实。

## 与日报的边界

评分只回答“岗位是否匹配”；日报还要回答“今天有哪些值得联系”。日报 Skill 负责二次筛选、排序和推送。
