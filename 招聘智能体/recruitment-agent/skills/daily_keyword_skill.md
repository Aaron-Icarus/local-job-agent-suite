# 每日搜索关键词 Skill（通用版）

## 目标

根据角色画像、求职意愿和历史搜索效果，单独生成：

1. AI 每日推荐关键词；
2. 人工高优关键词（用户手工维护，AI 不覆盖）；
3. 默认兜底关键词。

**关键词不写入角色画像 MD。**

## 关键词分组

| 分组 | 来源 | 用途 |
| --- | --- | --- |
| AI 每日推荐 `recommended` | 每次生成 | 下一轮主要搜索词，8–12 个 |
| 人工高优 `manual` | 用户手工添加 | 优先级最高，采集器先跑；AI 不得删除 |
| 默认兜底 `fallback` | AI/本地规则/人工调整 | 推荐词效果差时启动，3–5 个 |

采集顺序：`manual` → `recommended` → `fallback`。

## 输入

- 角色画像（已脱敏）；
- 目标岗位、城市、薪资；
- 职业期望（高权重）；
- 简历中的技能/经历；
- 历史关键词：使用次数、新增、重复、失败、最近使用；
- 用户当前的人工高优词和兜底词。

## 输出（只输出 JSON）

```json
{
  "recommended": ["岗位名A", "方向词B", "同义词C"],
  "fallback": ["较宽岗位名1", "较宽岗位名2"]
}
```

- `recommended`：8–12 个；
- `fallback`：3–5 个；
- 两者不重复；
- 不输出姓名、电话、邮箱、公司机密。

## 生成规则（跨专业通用）

1. **求职意愿优先**：目标岗位、职业期望、城市、薪资是最高权重；历史效果只做微调。
2. **岗位名 + 方向 + 同义词**：每个目标岗位至少给出标准岗位名、行业/领域组合、常见同义词/英文缩写。
3. **不要把所有行业都写成 AI**：用户是财务、法务、供应链、医疗、教育、设计、销售等，就按该专业生成；只有画像确实涉及 AI/数字化时才加 AI 词。
4. **不要过宽**：单独“经理”“工程师”“专员”不作为主推荐词；过宽词放兜底。
5. **不要过窄**：公司内部项目名、只有一家公司使用的缩写，不作为主推荐；可放兜底或不生成。
6. **城市/薪资不写进关键词**：它们是筛选条件，不是搜索词。
7. **历史轮换**：最近连续使用、重复率高、失败率高的词降低权重；仍能产出新岗位的词保留。
8. **人工高优优先**：人工词永远保留；AI 只补充，不覆盖、不删除。
9. **兜底必须存在**：即使 AI 失败，也要用本地规则生成 3–5 个兜底词。
10. **可解释**：每个推荐词应能对应画像中的目标岗位、技能或经历；不能对应则不要生成。

## 本地兜底规则

当 AI 不可用时：

- 从 `target_roles` 拆出标准岗位名；
- 从画像的“技能关键词/能力标签”提取 2–4 个方向词；
- 生成“岗位名 + 行业/领域”“岗位名 + 同义词”等组合；
- 兜底词使用较宽的岗位族词；
- 不生成城市、薪资、姓名、公司名。

## 存储与调用

- 当前词：`role_keyword_entries`，`category=recommended/manual/fallback`，`is_current=1`；
- 兼容采集：`roles.role_keywords_json`，按 manual → recommended → fallback 排序；
- 采集器：`task_service.collectKeywords(role)`，最多读取 12 个；
- 入口：
  - 新建角色：上传简历后自动生成画像 + 关键词；
  - 角色卡片“关键词”：查看三组、添加/删除人工词、生成下一轮；
  - API：`POST /api/keywords/generate`、`GET /api/roles/:id/keywords`、`POST /api/roles/:id/keywords/manual`。

## 质量校验

- [ ] 推荐 8–12 个、兜底 3–5 个；
- [ ] 人工词没有被覆盖；
- [ ] 没有城市/薪资/联系方式；
- [ ] 没有单独“经理/工程师/专员”这类过宽词作为主推荐；
- [ ] 每个词能对应画像中的岗位、技能或经历；
- [ ] 没有把非 AI 专业强行写成 AI 词。
