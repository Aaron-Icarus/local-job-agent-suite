# 角色画像生成 Skill（通用版）

## 目标

把用户上传的简历（DOC/DOCX/PDF/MD/TXT/图片文字）和目标条件，整理成一份**可检索、可评分、可追溯**的角色画像 Markdown。适用于任何专业领域，不假设用户是 AI、互联网或管理岗位。

## 输入优先级

1. 用户本次填写的目标岗位、城市、薪资、职业期望；
2. 原始简历中的事实；
3. 历史角色画像/对话中用户确认过的信息；
4. 缺失信息只能标注“待确认”，不能推断或编造。

## 简历读取与缺失信息判断

每次收到简历或进入画像流程时，先做一次字段检查，不要直接生成，也不要直接拒答：

1. **先确认简历是否读到了**：说明已读取到哪些内容（姓名、学历、工作经历等），不要只回“请上传简历”。
2. **必填字段**：简历、目标岗位、目标城市、期望薪资、相关经历。
3. **缺什么问什么**：只列出缺失项，并给一个可直接照抄的填写示例；不要重复询问已经有的信息。
4. **信息基本齐全**：简历、目标岗位、城市、薪资、经历都有时，直接生成画像，不再要求用户额外说“生成画像”。
5. **不确定用户是否要生成**：在回复中主动问一句“现在就按这些信息生成，还是先补充？”；如果用户明确说“先按现有信息生成”，允许生成，并把未确认项写入“风险/需确认”。
6. **不要用寒暄代替判断**：有简历但字段不全时，应该给出缺失清单和问题；有简历且字段齐全时，应该直接进入生成。

## 必须先保存原始材料

- 原始文件复制到 `data/resumes/files/`，并在 `resumes.file_path` 记录；
- 提取文本写入 `resumes.raw_md`；
- 图片/扫描件没有 OCR 时记录“无法识别”，不要凭空补内容；
- AI 处理失败时：保留原文件和提取文本，创建 `profile_tasks(status=pending)`，角色先用本地兜底画像，不能丢用户材料。

## 画像输出结构（必须保留标题）

```markdown
# 姓名 / 角色画像

## 基础信息
- 姓名：
- 学历/专业：
- 目标岗位：
- 目标城市：
- 期望薪资：
- 工作年限：

## 求职诉求
- 想要什么岗位/行业/业务：
- 城市与通勤：
- 薪资底线与期望：
- 偏好与限制：

## 职业发展期望
- 近期目标：
- 中长期方向：
- 不希望做的方向：

## 工作经历
### 公司 / 岗位 / 时间
- 职责：
- 项目/成果（尽量量化：规模、金额、效率、增长、交付周期）：
- 使用的工具/方法：

## 能力标签
- 专业能力：
- 业务/行业能力：
- 工具与方法：
- 协作/管理能力：

## 技能关键词
- 只写人物技能，不写每日搜索词；中英文均可。

## 求职偏好/避雷
- 用自然语言描述“想要什么、不想要什么”，不要只列关键词。

## 兜底关键词
- 3–5 个较宽的岗位名/方向词，供搜索效果差时兜底。

## 风险/需确认
- 简历中没有依据、或需要用户确认的内容。
```

## 提炼方法（跨专业通用）

1. **先事实后判断**：公司、岗位、时间、项目、数字必须来自简历；能力标签可以提炼但不能改变事实。
2. **用“动作 + 对象 + 结果”写经历**：例如“重构对账流程，把月结从 5 天降到 2 天”；不写空泛的“负责相关工作”。
3. **区分岗位族**：技术、产品、项目交付、运营、销售、财务、法务、人力、设计、供应链、医疗、教育等都可以用同一结构，不要硬套互联网黑话。
4. **技能分层**：领域知识 / 硬技能 / 工具 / 软技能 / 管理能力；避免把公司名、行业名当个人技能。
5. **可迁移能力**：跨行业求职时，提取流程优化、数据分析、客户沟通、项目管理、合规、规模化交付等可迁移点。
6. **关键词不过度堆砌**：每个能力标签要有简历依据；没有依据的标签放进“风险/需确认”。
7. **ATS 友好**：使用常见岗位名、标准技能名、中英文对照；避免只用内部缩写。
8. **不迎合单一模板**：不要因为某个行业流行“AI/智能体”就把所有经历改写成 AI；用户没有该背景时保持原方向。

## 隐私与安全

- 不写入：电话、手机号、邮箱、密码、验证码、身份证、微信、QQ、详细住址、紧急联系人。
- 城市只保留求职相关城市/区域，不保留门牌号。
- 不把简历原文、画像、联系方式上传到公开仓库或第三方公开服务。
- AI 输出后再次做隐私清洗；发现疑似联系方式必须删除。

## 质量校验

生成后逐项检查：

- [ ] 9 个二级标题齐全；
- [ ] 目标岗位、城市、薪资与用户输入一致；
- [ ] 没有编造公司、学历、证书、数字；
- [ ] 没有电话/邮箱/身份证/微信/QQ；
- [ ] 没有“每日搜索关键词”段落；
- [ ] 工作经历有时间、职责、成果；
- [ ] 能力标签能从简历找到依据；
- [ ] 缺失信息在“风险/需确认”里列出。

不满足时：能补则补；不能补则标记“待确认”，不要伪造。

## 与关键词模块的边界

画像只放“技能关键词”和“兜底关键词”，**不生成每日搜索关键词**。每日关键词由 `skills/daily_keyword_skill.md` 单独生成，保存到 `role_keyword_entries` / `roles.role_keywords_json`，并区分 AI 推荐、人工高优、默认兜底。

## AI 失败兜底

- 没有可用 AI 能力：生成本地结构化画像（不编造），角色 `profile_status=pending`；
- 记录失败原因和原始文件路径；
- 前台提示“角色已创建，画像待整理”；
- 后续 AI 调通后，允许按 `profile_tasks` 重新处理，不重复上传原文件。
