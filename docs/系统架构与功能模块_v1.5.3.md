# 第 1 章 总体架构

## 1.1 系统定位

这是一个本地运行的求职自动化客户端：

```text
简历 / 求职目标
→ 角色画像
→ 关键词
→ 招聘平台采集
→ 岗位入库 / 编号
→ AI 优先评分
→ 日报 / 飞书群
→ 打招呼话术 / Excel 导出
```

系统不包含：

- 自动投递；
- 自动聊天；
- 验证码破解；
- 绕过招聘平台风控；
- 云端多租户。

## 1.2 分层架构

```text
┌─────────────────────────────────────────────┐
│ 表现层：Electron 窗口 / 浏览器页面           │
│ ui/index.html、ui/app.js、ui/styles.css      │
└───────────────────┬─────────────────────────┘
                    │ 本地 HTTP / JSON
┌───────────────────▼─────────────────────────┐
│ 应用层：本地 API 与业务编排                   │
│ app_server.js、chat_service、task_runner      │
└───────────────────┬─────────────────────────┘
                    │
┌───────────────────▼─────────────────────────┐
│ 领域服务层                                    │
│ 角色 / 画像 / 采集 / 入库 / 评分 / 关键词     │
│ 日报 / 飞书 / 导出 / 登录 / 调度              │
└───────┬─────────────────────┬───────────────┘
        │                     │
┌───────▼────────┐   ┌────────▼──────────────┐
│ SQLite 数据层   │   │ 外部能力               │
│ jobs.db WAL     │   │ Chrome CDP / AI API    │
│ 文件原始队列    │   │ 飞书 Open API / Webhook│
└────────────────┘   └───────────────────────┘
```

## 1.3 运行进程模型

```text
Electron 主进程
├─ BrowserWindow：加载本地 UI
├─ Tray：托盘、显示窗口、退出
└─ 子进程：本地 Node 后端
   ├─ HTTP API
   ├─ SQLite
   ├─ 任务 Worker
   ├─ Chrome CDP 子进程
   ├─ BOSS/猎聘采集脚本子进程
   └─ 消息平台长连接子进程（按需启动）
```

关键点：

- Electron 不直接写业务数据库；
- 业务都通过本地 Node 后端 API；
- Chrome 不由 Electron 内置，使用本机 Google Chrome；
- 后端使用 Node.js 22.5+ 的 `node:sqlite`，所以安装包必须内置 Node 22+；
- 关闭窗口默认隐藏到托盘，不直接退出。

## 1.4 数据与文件位置

Windows 安装版：

```text
<安装目录>\data\v1.4\jobs.db
<安装目录>\data\logs\app.log
<安装目录>\data\exports\
<安装目录>\data\ChromeProfile\
<安装目录>\message-platform\
```

macOS：

```text
~/Library/Application Support/JobAgent/...
```

开发模式：

```text
招聘智能体/recruitment-agent/data/v1.4/jobs.db
```

数据库使用 WAL 模式，所有角色、岗位、评分、任务、画像、日报和日志索引都在 SQLite 中。

## 1.5 核心设计原则

1. **先保存事实，再做判断**：采集原始数据先落文件，再入库、编号、评分。
2. **岗位库与角色评分分离**：`jobs` 是公共岗位事实；`role_jobs` 是按角色独立的评分与备注。
3. **AI 优先，规则兜底**：画像、关键词、岗位评分优先调用 AI；AI 不可用时保留可解释的本地结果。
4. **硬条件不被 AI 改写**：关闭、重复、薪资/城市等岗位事实由程序控制。
5. **所有状态可恢复**：任务、评分、画像、日报都有状态和时间字段。
6. **本地优先与隐私优先**：数据、日志、Chrome Profile 默认留在本机；密钥加密存储。

## 1.6 端到端主流程

```text
触发（定时 / 手动 / 启动补齐）
→ 任务队列 tasks
→ 采集 collect
→ outputs 原始 JSON
→ 入库 ingest
→ jobs / role_jobs
→ 评分 score（AI 优先）
→ 日报 report
→ 飞书群 / 本地通知
```

完整状态：

```text
待采集 → 采集中 → 采集成功/部分成功/失败
→ 待入库 → 入库中 → 已入库/待补
→ 待评分 → 评分中 → 已评分
→ 待生成日报 → 已生成 → 已发送/发送失败
```

## 2.2 模块依赖关系

```text
UI
→ app_server
  → role_service / roles_repo
  → chat_service → intent_service / resume_parser / profile_generator
  → task_service → tasks_repo
  → score_service → ai_providers + scores_repo
  → keyword_service
  → report_service / feishu_groups
  → login_checker / chrome_manager
  → export_service

task_runner
→ collection_runner → Chrome + 平台脚本
→ ingest_service → jobs_repo / raw_queue / jd_cleaner
→ score_service
→ report_service
→ export_service
```

## 2.3 角色生命周期

```text
新建角色（pending_confirm）
→ 确认渠道（pending_start）
→ 首次启动（running，锁定目标/画像/关键词）
→ 暂停（paused）
→ 继续（running）
→ 复制（新角色、新 UUID、新编号、空评分库）
→ 软删除
```

规则：

- 最多 3 个活动角色；
- 首次启动后不可直接修改，只能暂停、继续或复制；
- 角色评分库独立，同一岗位对不同角色有不同分；
- 角色目标岗位统一拆成 `岗位A、岗位B`。

## 2.4 岗位生命周期

```text
采集原始记录
→ 校验：平台唯一 ID + 完整 JD
→ 不合格：pending_jobs 待补
→ 合格：jobs 新增/更新
→ 按平台编号
→ 跨渠道重复标记
→ 同步到每个角色的 role_jobs
→ 等待评分
```

岗位关闭、重新开放、内容变化都会触发对应角色重新评分。

## 2.5 任务协作流程

```text
scheduler / 手动操作
→ task_service 创建 tasks
→ task_runner 每 2 秒取一个任务
→ 单任务执行
→ 成功 finishTask / 失败 failTask（可重试）
```

任务类型：

```text
collect  采集
ingest   入库
score    评分（AI 优先）
report   日报
export   Excel / 日志导出
```

任务优先级：

```text
日报/推送 > 评分 > 入库 > 采集
```

采集任务还会受：

- 采集时间段；
- 最小间隔；
- 每天最低次数；
- R-2h/R-1h 兜底；
- 系统空闲/CPU/电量；
- 手动强制。

# 第 3 章 模块详解

## 3.1 桌面壳与启动器

**职责**

- 创建 Electron 窗口和托盘；
- 选择随机本地端口；
- 启动后端 Node 子进程；
- 等待后端健康检查；
- 加载本地 UI；
- 关闭窗口时隐藏到托盘。

**逻辑**

```text
app.whenReady
→ 选择空闲端口
→ 确定 runtime / node
→ 准备用户数据目录
→ spawn 后端
→ 轮询 /api/health
→ BrowserWindow.loadURL
→ 创建托盘
```

**关键文件**

- `electron/main.js`
- `electron/preload.js`
- `scripts/prepare-runtime.js`

**关键点**

- 安装版使用 `resources/runtime` 中的 Node；
- Windows 数据在安装目录 `data`；
- macOS 数据在用户数据目录；
- 默认关闭窗口不退出，托盘可恢复；
- 单实例锁失败时仍允许启动，避免旧 ACL 导致完全打不开。

## 3.2 本地 API 与页面

**职责**

- 提供 JSON API；
- 提供静态 UI；
- 统一错误处理；
- 把业务服务暴露给页面。

**页面**

```text
首页 / 角色 / 任务 / 职位库 / 设置
AI 能力 / 消息 / 日报 / 对话
```

**主要 API 分类**

- `/api/health`、`/api/settings`
- `/api/roles`、`/api/roles/:id/...`
- `/api/resume/extract`、`/api/resumes`
- `/api/chat/sessions`
- `/api/tasks`、`/api/tasks/board`
- `/api/jobs`、`/api/jobs/:id`
- `/api/ai/providers`
- `/api/login`、`/api/chrome`
- `/api/feishu-groups`、`/api/feishu-routing`
- `/api/message-platform`
- `/api/reports`
- `/api/export`
- `/api/keywords`

**实现**

- `app_server.js` 使用 Node `http`；
- 读取 JSON body；
- 统一 `json(res, status, payload)`；
- 静态文件从 `ui/` 读取；
- 复杂业务调用领域服务，不在路由里写业务算法。

## 3.3 数据层

**数据库**

SQLite，WAL 模式，`node:sqlite`。

核心表：

```text
roles                 角色
resumes               简历原文与解析
role_jobs             角色 × 岗位评分
jobs                  公共岗位事实
role_keyword_entries  关键词分组
keyword_tasks         关键词执行统计
tasks                 任务队列
task_events           任务事件
collection_events     采集事件
collection_subtasks   采集子任务
raw_files             原始采集文件
pending_jobs          待补岗位
reports               日报
login_checks          登录检查
feishu_groups         飞书群
feishu_group_roles    群 × 角色通知
settings              设置
ai_providers          AI 供应商
chat_sessions         对话会话
chat_messages         对话消息
```

**实现原则**

- 仓储层负责 SQL，不把 SQL 散落在 UI；
- 状态变化都写时间；
- 岗位事实与角色评分分离；
- 原始文件、解析文本、画像和评分均可追溯。

## 3.4 角色与画像

**输入**

- 简历文件：MD/TXT/DOCX/PDF/DOC；
- 目标岗位、城市、薪资、经历、职业期望；
- 用户对话中的偏好/避雷。

**处理**

```text
文件
→ document_text 提取文字
→ resume_parser 结构化解析
→ 缺失字段检查
→ profile_generator / resume_profile_skill
→ AI 生成画像
→ 本地兜底
→ 角色
```

**画像结构**

```text
基础信息
求职诉求
职业发展期望
工作经历
能力标签
技能关键词
求职偏好/避雷
兜底关键词
风险/需确认
```

**隐私**

- 电话、邮箱、身份证、微信、QQ 不进入画像；
- 原文件只在本机保存；
- 画像和原始简历不进入公开仓库。

**关键文件**

- `document_text.js`
- `resume_parser.js`
- `profile_generator.js`
- `role_service.js`
- `roles_repo.js`
- `skills/resume_profile_skill.md`

## 3.5 对话与意图识别

**意图类别**

```text
profile_create   生成画像
profile_update   调整画像
job_search       查岗位
job_detail       岗位详情
greeting         生成打招呼
clarify          意图不明确，主动询问
chat             普通对话
```

**判断顺序**

```text
明确画像指令
→ 简历/偏好上下文
→ 岗位搜索
→ 岗位详情
→ 打招呼
→ 普通对话/澄清
```

**画像对话逻辑**

- 已读简历先说明识别到哪些字段；
- 缺字段只问缺的；
- 信息齐全直接生成；
- 用户说“先按现有信息生成”允许带待确认项生成；
- 用户说“不要/不考虑/重点看”保存为偏好和避雷；
- “更新画像”使用当前画像 + 最新偏好重新生成；
- 关键词/画像过滤避雷方向。

**关键文件**

- `intent_service.js`
- `chat_service.js`

## 3.6 采集与 Chrome

**Chrome 管理**

- 查找本机 Google Chrome；
- 检查 CDP 端口；
- 启动独立 `--user-data-dir`；
- CDP 就绪后执行采集；
- 支持最小化/恢复/关闭。

**采集事件**

```text
collection_event
→ 按 平台 × 角色 拆子任务
→ 每个子任务读取关键词任务
→ spawn 平台采集脚本
→ 子任务成功/失败
→ 汇总采集事件
```

**平台**

- BOSS；
- 猎聘。

**采集结果**

- 原始 JSON 写入 `outputs`；
- 交入库队列；
- 不直接写业务评分。

**空闲策略**

- 用户活跃时采集任务延后；
- 手动强制采集可绕过；
- CPU/电量策略由设置控制。

**关键文件**

- `chrome_manager.js`
- `collection_runner.js`
- `src/platforms/boss/*`
- `src/platforms/liepin/*`
- `idle_policy.js`
- `system_idle.js`

## 3.7 登录检测

**检查内容**

- Chrome 是否启动；
- 页面是否登录；
- 是否出现安全验证；
- BOSS/猎聘业务接口是否返回有效岗位。

**结果**

```text
logged_in
login_required
security_check
browser_error
timeout
```

**记录**

- `login_checks` 记录平台、状态、时间、错误；
- 12 小时节流；
- 异常可发飞书通知。

**关键文件**

- `login_checker.js`
- `login_monitor.js`
- `src/platforms/*/check_*_login_status.js`

## 3.8 入库与岗位库

**原始队列**

- 发现 `outputs` 新文件；
- 标记 pending；
- 防止重复处理；
- 失败可重试。

**入库校验**

- 平台唯一 ID；
- 必填岗位信息；
- JD 长度；
- 不满足进 `pending_jobs`，不占编号。

**去重**

- 平台内唯一键；
- 跨渠道相似岗位标记 `duplicate`；
- 重复岗位保留记录，但不参与推荐。

**编号**

- 按平台独立序列；
- 真正入库时分配；
- 编号作为用户可引用 ID。

**JD 清洗**

- 保留原始 JD；
- 清洗导航/广告/推荐；
- 提取招聘方、在线时间、认证、HC；
- 生成 `jd_clean_text`。

**关键文件**

- `raw_queue.js`
- `ingest_service.js`
- `jobs_repo.js`
- `jd_cleaner.js`

## 3.9 评分（AI 优先）

**输入**

- 岗位事实、JD；
- 角色画像；
- 目标岗位/城市/薪资；
- 角色关键词；
- `skills/job_scoring_skill.md`。

**流程**

```text
选择待评分岗位
→ 本地规则算参考分
→ AI Provider 直接输出 0–100 最终分
→ AI 成功：保存 v1.5.3-ai-first
→ AI 失败/异常：保存 v1.5-local-fit
→ 写 role_jobs
```

**AI 输出**

- score；
- reasons；
- risks；
- summary；
- tier 由分数区间生成。

**硬条件**

- AI 不修改岗位事实；
- 关闭/重复岗位不进入正常推荐；
- AI 不编造简历或岗位经历。

**目标岗位**

- `项目经理和产品经理` → `项目经理、产品经理`；
- 评分使用通用中文/英文词组，不写死 AI/行业词表。

**入口**

- 角色卡片“重新评分”；
- 任务队列 `score`。

**关键文件**

- `score_service.js`
- `scores_repo.js`
- `skills/job_scoring_skill.md`

## 3.10 关键词

**输入**

- 角色画像；
- 目标岗位/城市/薪资；
- 历史关键词执行效果；
- `skills/daily_keyword_skill.md`。

**输出**

```text
recommended  8–12 个 AI 推荐词
manual       用户人工高优词
fallback     3–5 个兜底词
```

**逻辑**

- AI 优先；
- 历史使用次数、重复率、失败率用于轮换；
- 人工词优先，AI 不覆盖；
- AI 失败时使用本地关键词。

**存储**

- `role_keyword_entries`
- `roles.role_keywords_json`

**关键文件**

- `keyword_service.js`
- `chat_service.js`
- `skills/daily_keyword_skill.md`

## 3.11 日报与飞书

**日报生成**

```text
运行中角色
→ 当天的 role_jobs
→ 评分 ≥ 60
→ 排除关闭/重复/长期不在线/过旧
→ Markdown 日报
→ 保存 reports
```

**飞书**

- 当前只支持一个飞书应用/机器人；
- 一个机器人最多 10 个群；
- 群 × 角色 × 通知节点：登录/异常/日报；
- 群内 @机器人进入本地对话；
- 无匹配群时只写本地通知；
- 测试消息当前为文本，不是卡片。

**消息平台**

- 独立长连接进程；
- App ID/Secret 在 `.env`；
- “同步群”只是把本地群写给消息平台，不会自动发现飞书新群；
- 启动长连接用于接收，不用于发送测试。

**关键文件**

- `report_service.js`
- `feishu_groups.js`
- `feishu_sender.js`
- `message_platform_service.js`

## 3.12 任务与调度

**任务状态**

```text
queued → running → success
                 → failed
                 → retrying
                 → paused / cancelled
```

**调度**

- 采集窗口；
- 每天最低次数；
- 1 小时最小间隔；
- 12:30 强制采集；
- R-2h 兜底；
- R-1h 入库/评分/日报；
- 日报时间窗；
- 空闲/CPU/电量。

**任务 Worker**

- 2 秒轮询；
- 单任务串行；
- 失败记录错误；
- 成功后创建下游任务。

**关键文件**

- `scheduler.js`
- `task_service.js`
- `task_runner.js`
- `tasks_repo.js`

## 3.13 AI Provider 与 Skill

**Provider**

- OpenAI 兼容接口；
- Codex 本地命令占位；
- 多供应商排序；
- 逐级降级；
- Key 加密；
- 测试连接。

**使用的 Skill**

```text
resume_profile_skill.md   画像
daily_keyword_skill.md    关键词
job_scoring_skill.md      评分
jd_cleaning_skill.md      JD 清洗
daily_report_skill.md     日报
usage_skill.md            使用说明
```

**原则**

- AI 不覆盖硬条件；
- AI 失败有本地兜底；
- AI 输入尽量脱敏；
- 不把真实密钥写入日志或仓库。

## 3.14 导出、日志与诊断

**导出**

- Excel：岗位、评分、理由、链接；
- 日志：按日志目录打包；
- 任务队列执行，避免阻塞页面。

**日志**

- `data/logs/app.log`；
- 本地滚动/大小限制；
- 记录 HTTP、任务、错误；
- 不记录密钥和完整敏感材料。

**诊断**

- `npm run doctor`；
- `npm run path:audit`；
- 启动日志；
- `startup.log`。

## 3.15 安装包与跨平台

**Windows**

- 便携 ZIP；
- `安装招聘智能体.cmd` 选择安装目录；
- 桌面/开始菜单快捷方式；
- 内置 Node 22+；
- Chrome 使用本机安装；
- 数据在安装目录 `data`。

**macOS**

- electron-builder DMG；
- GitHub Actions macOS runner；
- `.app` 放入 Applications；
- 数据在 `~/Library/Application Support/JobAgent`；
- 未签名时需要“隐私与安全性”允许。

**注意**

- 单文件旧 setup.exe 不是最新交付；
- 最新以 `招聘智能体-1.5.3-portable.zip` 或 Actions artifact 为准；
- Windows 和 macOS 不能共用可执行文件。

# 第 4 章 当前边界与后续方向

## 4.1 当前边界

- 一个飞书机器人、最多 10 个群；多机器人尚未实现；
- AI 评分按批次调用，批量 6 个岗位/请求，失败项补一次；
- AI 不可用时保留本地分，`score_version=v1.5-local-fit`；
- 图片简历不做 OCR；
- Chrome 登录/风控仍需人工处理；
- macOS 未做签名/公证；
- 不做自动投递和自动聊天。

## 4.2 后续可演进

1. 多飞书机器人：`feishu_bots` + `feishu_groups.bot_id`；
2. 评分结果缓存：相同画像/岗位/模型复用 AI 结果；
3. 多平台采集适配器；
4. 更细的岗位画像和评分解释；
5. macOS 签名、公证、双架构 DMG；
6. 任务可视化与运行指标；
7. 更完整的本地审计和权限模型。
