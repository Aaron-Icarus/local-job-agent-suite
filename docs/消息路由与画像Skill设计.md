# 消息路由与画像 Skill 设计

## 1. 消息页结构

正常页面只展示结果：

1. 飞书应用状态（App ID/Secret/群 ID 是否已配置、服务是否运行）；
2. 已有群配置列表：群名、Chat ID、绑定角色、通知节点、是否默认群；
3. 最近通知：时间、类型、标题、发送状态；点击单条查看完整正文；
4. 右上角“调整配置”进入弹窗；右上角“?”打开飞书配置帮助。

“调整配置”弹窗内完成：

- 新增/修改群；
- 勾选角色；
- 勾选通知节点（登录状态、操作异常、每日日报）；
- 一键填充运行中角色；
- 保存并确认；
- 同步群到消息平台；
- 设为默认群。

## 2. 多对多路由

```text
飞书群 A ── 角色 R001（登录/异常）
         └─ 角色 R002（日报）

飞书群 B ── 角色 R001（日报）
         └─ 角色 R003（异常/日报）
```

数据库：

- `feishu_groups`：群、Chat ID、webhook、是否默认、群回复角色；
- `feishu_group_roles`：群 × 角色 × 三个通知节点。

所以同一角色可以发到多个群，同一群可以接收多个角色；不同阶段可以落到不同群。

## 3. 默认通知群

- 每个群可设为默认；
- 新角色创建时，自动把该角色加入默认群（登录/异常/日报全开）；
- 没有默认群时，不自动分配；通知只写本地历史，不外发；
- 默认群只影响“新角色默认路由”，不覆盖已有手工配置。

## 4. 群内 @机器人 回复

```text
飞书 @机器人
  → 长连接收到事件
  → 根据 chat_id 找到群配置
  → 用 group.reply_role_uuid 选择回复角色
  → 调本地 /api/chat
  → 按意图执行：
       查岗位 / 查 JD / 查评分 / 查日报 / 写打招呼 / 生成画像
  → 回复到群
```

群回复角色单独配置，避免“一个群绑了多个角色时不知道用哪个角色回答”。

回复工具：

- `search_jobs`：按角色评分查岗位，输出编号、公司、岗位、评分；
- `job_detail`：按编号查薪资、地点、评分、链接、JD；
- `greeting`：结合角色画像 + 岗位 JD，生成 100–200 字打招呼；
- `report`：按角色查最近日报；
- `profile`：生成/更新角色画像。

## 5. 画像 Markdown 设计

必须包含：

- 基础信息：姓名、学历、专业、目标岗位、城市、薪资；
- 职业发展期望：方向、优先岗位、关注领域；
- 工作经历：按时间倒序，保留项目金额、团队规模、成果；
- 能力标签；
- 风险/需确认。

**不得包含：**

- 电话、手机、邮箱、密码、身份证、微信、QQ、联系方式；
- 技能关键词；
- 每日搜索关键词；
- 搜索排除词。

每日关键词单独生成，保存到 `roles.role_keywords_json`，不进入画像。

示例（结构示意，不含真实个人数据）：

```text
# <姓名> 角色画像
## 基础信息
- 目标岗位：<目标岗位>
- 目标城市：<目标城市>
- 期望薪资：<目标薪资>
## 职业发展期望
<行业/职能方向>
## 工作经历
<按时间倒序>
## 能力标签
<从真实经历提炼>
## 风险/需确认
<缺失信息>
```

## 6. 每日关键词生成规则

1. 从目标岗位拆主关键词；
2. 从工作经历拆技术/业务关键词；
3. 生成同义组合（AI项目经理/AI项目交付/AI产品经理/智能体项目经理）；
4. 城市、薪资只作为筛选条件，不混进关键词；
5. 排除过宽词（单独“项目经理”）和不相关方向；
6. 控制在 8–12 个，后续按采集结果反馈调整；
7. 角色创建后写入 `role_keywords`，供采集器使用。

## 7. 角色关键词记录

- 表：`role_keyword_entries`；`category=recommended/fallback`，`is_current=1` 表示当前轮；
- 兼容字段：`roles.role_keywords_json` 供采集器读取；
- 历史效果：同一角色在 `keyword_tasks` 中的 seen/new/duplicate/failed/最近使用；
- 生成时用户画像与意愿权重最高，历史效果用于轮换和降权；
- 角色页“关键词”弹窗显示下一轮推荐、兜底和历史统计。
