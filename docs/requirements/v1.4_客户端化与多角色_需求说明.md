# v1.4 客户端化与多角色 需求说明

- 版本：v1.4.1
- 日期：2026-11-05
- 状态：v1.4.1 已开发（MVP，待真实平台回归）
- 关联：`CHANGELOG.md`、`docs/v1.3_改造说明.md`、`docs/prd/招聘信息智能体_客户端_PRD_v3.0.md`

---

## 1. 背景与目标

当前项目是 CLI + Windows 计划任务的散代码形态，采集、入库、评分、日报之间的时间和任务状态不透明；岗位评分只能保存一个候选人的结果，无法支持多角色；采集卡住、登录失效、风控时缺少通知和人工介入。

v1.4 的目标：

1. 把项目升级为 **Windows 桌面客户端**（Electron），可安装、可托盘、可持续运行；
2. 建立 **采集任务 / 子任务 / 关键词任务** 队列和状态机，可暂停、恢复、重试、关闭；
3. 建立 **公共岗位库 + 按角色独立评分库**，支持同一 Windows 用户最多 3 个角色；
4. 采集与入库解耦：采集先写原始文件，入库队列处理所有未入库文件；
5. 调度支持采集窗口、最低次数、最小间隔、空闲策略、R-2h 兜底、R-1h 入库/评分/日报；
6. 提供角色、任务、设置、AI 能力、日报、职位库等页面；
7. 支持多平台单账号、登录检测、风控/卡住通知、人工介入；
8. 支持 AI 关键词生成、AI 评分、模型 API 多供应商排序与逐级降级；
9. 支持 Excel 导出，岗位链接可在 Excel 中直接打开。

---

## 2. 范围

### 2.1 本期范围

- Windows 10/11 桌面客户端；
- BOSS、猎聘两个渠道，每个渠道仅一个当前登录账号；
- 同一 Windows 用户最多 3 个角色；
- 公共岗位库、角色评分库；
- 采集队列、入库队列、评分任务、日报任务；
- 关键词生成与人工干预；
- 飞书群机器人日报；
- Excel 导出；
- AI 供应商配置与降级。

### 2.2 非目标

- 不做自动投递、自动聊天、验证码自动破解；
- 不绕过平台风控；
- 不做多 Windows 用户隔离/云端 SaaS；
- 不打包 Google Chrome；
- 不做多账号同时登录/并发采集；
- 不做移动端。

## 3. 角色与权限

| 角色 | 说明 |
| --- | --- |
| 使用者 | 本机 Windows 用户；管理角色、任务、设置、AI、日报、职位库 |
| 招聘渠道 | BOSS、猎聘；每个渠道一个当前账号 |
| 角色（求职角色） | 一套简历/画像/目标/关键词/评分规则；最多 3 个 |
| 系统任务 | 采集、入库、评分、日报、登录检查、导出等后台任务 |

## 4. 功能需求

### 4.1 角色管理

- **REQ-ROLE-01** 角色列表展示编号、昵称、状态、创建时间、最近修改时间、渠道、关键词数量、评分数量。
- **REQ-ROLE-02** 支持新建角色：上传/粘贴简历 → AI 识别 → 生成岗位背景 Markdown → 设置目标岗位、目标城市、薪资、特殊要求 → 可 AI 对话调整。
- **REQ-ROLE-03** 角色状态：`待确认`、`待启动`、`运行中`、`已暂停`。
- **REQ-ROLE-04** 待确认可修改；确认后未首次启动仍可修改；**首次启动后永久锁定**，只能暂停/继续/复制。
- **REQ-ROLE-05** 已确认未启动的角色修改后，必须重新确认并重新做相似度检查。
- **REQ-ROLE-06** 确认时做本地相似度 + AI 相似度检查；高重合提示“与角色 X 高度重合”，允许仍然确认（因为最多 3 个角色）。
- **REQ-ROLE-07** 复制角色生成新 UUID、新编号、新昵称，状态为待确认，评分库为空。
- **REQ-ROLE-08** 最多 3 个角色；角色和评分库均软删除，不物理删除。
- **REQ-ROLE-09** 每个角色独立设置：关键词、渠道、评分规则、AI 供应商、日报通道。
- **REQ-ROLE-10** 角色记录建立时间、修改时间、确认时间、首次启动时间。

### 4.2 任务与关键词

- **REQ-TASK-01** 任务板块展示：渠道状态、当前执行任务、历史任务、子任务、关键词任务、日志。
- **REQ-TASK-02** 每天调用 AI，结合简历、目标、画像、采集历史，为每个角色生成/更新关键词；每个角色最多 6 个。
- **REQ-TASK-03** 展示运行中 3 个角色当天的关键词及排序；支持人工添加/删除/调整数量。
- **REQ-TASK-04** 默认每天按优先级执行其中 2 个关键词；可配置执行 1–6 个；人工可调整。
- **REQ-TASK-05** 关键词记录：所属角色、关键词、渠道、优先级、执行次数、成功/失败/重复/新增、最近执行时间。
- **REQ-TASK-06** 一次采集 = 一个整体事件；内部按“平台 × 角色”拆子任务（2×3=6）；同一平台只使用一个当前账号。
- **REQ-TASK-07** 子任务独立状态：成功/部分成功/失败；记录关键词明细、页数、停止原因、耗时。
- **REQ-TASK-08** 采集执行即计数；子任务成功/失败单独记录；失败子任务在采集窗口内可重试，单子任务短时间最多 3 次。
- **REQ-TASK-09** 任务状态机：排队、运行、暂停、成功、失败、重试、取消；支持单个子任务/整体事件暂停、继续、重试、强制关闭。
- **REQ-TASK-10** 任务卡住 5 分钟只通知不自动重启；子任务新标签页重试 3 次（每次等待 1 分钟），失败跳过；同平台第二个子任务卡住则切另一平台。
- **REQ-TASK-11** 任务完成或全部关闭后关闭 Chrome 实例，避免空白浏览器。
- **REQ-TASK-12** 任务日志按角色/平台/子任务/关键词记录，支持后续分析。

### 4.3 调度与设置

- **REQ-SCHED-01** 采集周期：全天、工作日、指定周几；采集时间段默认 09:00–18:00，可设全天。
- **REQ-SCHED-02** 最低采集次数默认 2 次/日；最小间隔默认 3 小时，最低 1 小时；每小时最多 1 次；设置小于 1 小时时弹窗并自动改为 1 小时。
- **REQ-SCHED-03** 12:30 检查：当天执行次数为 0 时强制采集一次（绕过空闲，不绕过 1 小时间隔）。
- **REQ-SCHED-04** 采集窗口结束前：执行次数不足最低次数时，在间隔/时间允许下补采一次。
- **REQ-SCHED-05** R-2h（默认 19:00）：当天 0 次时强制采集；勾选“录入时再采集”也尝试一次；默认允许越过 09:00–18:00；仍守 1 小时间隔。
- **REQ-SCHED-06** R-1h（默认 20:00）：立即停止采集，不等待；入库所有未入库 raw，评分，生成日报；R 点发送。
- **REQ-SCHED-07** 填报日报时间默认 21:00，窗口 19:00–22:00。
- **REQ-SCHED-08** 空闲策略：键鼠空闲分钟数、CPU 上限、电量下限；软/硬策略；强制采集只绕过空闲。
- **REQ-SCHED-09** 任务优先级：日报/推送最高，评分次之，入库低开销可随时，采集最重且受窗口/空闲/间隔限制。
- **REQ-SCHED-10** 入库可后台随时跑；每天固定时间只是兜底。
- **REQ-SCHED-11** 统计最近 7 次采集/入库/评分平均耗时；时间不足时优先入库/评分/日报，跳过采集。
- **REQ-SCHED-12** 采集窗口可设为 4 小时等；窗口内可安排多次采集事件，事件间守 1 小时间隔。

### 4.4 采集与浏览器

- **REQ-BROWSER-01** Electron 不打包 Chrome；检测本机 Chrome。
- **REQ-BROWSER-02** 程序管理 Chrome 启动、最小化/隐藏、唤醒、关闭；不把 Chrome 窗口嵌入 Electron。
- **REQ-BROWSER-03** Chrome 可最小化后台运行；人工可随时唤醒查看、登录、处理验证码，再最小化。
- **REQ-BROWSER-04** 显示当前任务、当前关键词/页码/岗位、运行时长、心跳、是否卡住、是否风控。
- **REQ-BROWSER-05** 登录检查：启动软件检查两个渠道；之后每 12 小时一次；睡眠/唤醒后若超过 12 小时立即检查；失败红灯 + 通知 + 记录。
- **REQ-BROWSER-06** 任务板块顶部显示两个渠道状态，可点击唤出浏览器进入登录页。
- **REQ-BROWSER-07** 触发风控/验证码立即暂停该平台任务并通知，不自动绕过。
- **REQ-BROWSER-08** 不自动重启 Chrome；人工可重试/重启任务，但重启不等于绕过验证。

### 4.5 入库队列

- **REQ-INGEST-01** 采集先写 raw 文件，登记 `pending`；入库 worker 处理所有未入库 raw（不只当天）。
- **REQ-INGEST-02** raw 状态：pending/processing/done/failed/archived；失败重试。
- **REQ-INGEST-03** 入库必须平台唯一 ID + 完整 JD；否则进待补，不占编号。
- **REQ-INGEST-04** 岗位编号全局唯一、写库时分配、连续不回收；跨渠道重复仍入库占号但标重复。
- **REQ-INGEST-05** 岗位记录采集时间、首次采集时间、最近采集时间、入库时间；11 号采集 12 号入库，展示 11 号。
- **REQ-INGEST-06** 入库按平台 + 平台岗位 ID 幂等，重复处理不重复建岗位/占号。
- **REQ-INGEST-07** 已入库 raw 标 done/归档，保留可配置天数；待补记录保留。
- **REQ-INGEST-08** 再次看到老岗位要更新最近采集时间、状态、状态更新时间；关闭后重新在招要恢复 open 并重新进入评分。

### 4.6 岗位库与角色评分

- **REQ-DATA-01** 公共岗位库只存客观事实：岗位信息、平台 ID、来源账号、采集/入库时间、状态、重复、状态更新时间、长期天数。
- **REQ-DATA-02** 每个角色独立评分库，记录 job_uuid、岗位编号、状态/重复快照、状态更新时间、评分、评分时间、说明、备注、是否打招呼、`needs_score`。
- **REQ-DATA-03** 主库是事实源；角色库状态快照与主库同步；主库变更发事件。
- **REQ-DATA-04** 角色评分先处理新岗位/无评分/评分早于角色修改时间/入库晚于角色修改时间的岗位；按岗位更新时间（内容/状态更新时间，不含单纯 last_seen）从新到旧；单次最多 100 个；有额度再处理旧岗位。
- **REQ-DATA-05** 岗位关闭/重新开放先标记 `needs_score`；只有需要发日报的角色重新评分，节省 token。
- **REQ-DATA-06** 首次采集超过 30 天为长期岗位，保留并提示，不直接跳过。
- **REQ-DATA-07** 支持按角色查看岗位、评分、推荐理由、风险、备注、打招呼状态。
- **REQ-DATA-08** 支持软删除角色和评分库。

### 4.7 AI 能力

- **REQ-AI-01** AI 能力页面配置多个供应商：OpenAI 兼容 API 与 Codex 本地命令；名称、Base URL、模型/命令、Key、排序、启用/关闭、测试、删除。
- **REQ-AI-02** Key 用 Windows DPAPI/凭据加密，不存明文；UI 只显示掩码。
- **REQ-AI-03** 支持按排序逐级尝试；前一个失败自动用下一个；全部失败报错；支持手动重启检测并逐级重试。
- **REQ-AI-04** 连接成功显示绿色；无 AI/全部失败时走规则兜底（关键词、评分、话术）。
- **REQ-AI-05** 角色可覆盖全局 AI 供应商；AI 缓存 key 包含角色、规则版本、候选人版本。
- **REQ-AI-06** AI 生成关键词：每天结合简历、目标、画像、采集历史生成/排序，最多 6 个/角色。
- **REQ-AI-07** AI 不推翻硬条件；岗位评分优先调用 AI，AI 直接给出匹配分和解释，不再限制 ±8 分。
- **REQ-AI-08** 只有 AI 不可用、调用异常、超时或返回非法结果时，评分才回退本地确定性规则；兜底必须记录 AI 异常和 `score_version`。

### 4.8 日报与通知

- **REQ-REPORT-01** 日报模块配置飞书群机器人（目前仅此渠道）；按角色分配通知通道。
- **REQ-REPORT-02** 默认只有“运行中”角色需要分配飞书通知通道。
- **REQ-REPORT-03** 日报日志按天/角色展示，只保留 2 周。
- **REQ-REPORT-04** 日报生成时间默认 21:00；R-1h 生成，R 点发送。
- **REQ-REPORT-05** 日报内容：岗位、评分、推荐等级、理由、风险、链接、采集日期、长期标记。
- **REQ-REPORT-06** 重要事件同时发 Windows Toast + 托盘 + 飞书（登录失效、风控、卡住、任务失败、日报发送失败）。

### 4.9 职位库与 Excel

- **REQ-EXPORT-01** 职位库按角色筛选，选择哪个角色导出哪个角色。
- **REQ-EXPORT-02** 默认导出到系统下载文件夹，可修改路径。
- **REQ-EXPORT-03** 字段：岗位 UUID、编号、平台、账号、公司、岗位、薪资、地点、采集日期、入库日期、状态、重复于、长期天数、评分、等级、理由、风险、链接。
- **REQ-EXPORT-04** 链接写成 Excel 超链接，可直接打开。
- **REQ-EXPORT-05** 冻结表头、自动筛选；支持当前筛选/全部。

### 4.10 客户端与安装

- **REQ-APP-01** Electron 桌面客户端，Windows 10/11，托盘、单实例、开机自启可选。
- **REQ-APP-02** 关闭窗口最小化到托盘；托盘菜单显示/暂停/继续/立即执行/退出。
- **REQ-APP-03** 安装包 NSIS，按用户安装；安装时检测 Chrome。
- **REQ-APP-04** 崩溃后任务可恢复；队列状态持久化。
- **REQ-APP-05** 日志、错误、任务状态可见；不上传隐私数据。

## 5. 数据与状态原则

- 岗位事实与角色评分分离；
- 主库全局唯一岗位编号；
- 角色库独立 `role_uuid`、评分序号；
- 所有状态变化记录时间；
- 采集时间与入库时间分开；
- 角色首次启动后锁定；
- 软删除；
- 任务状态可恢复；
- 原始文件不可变，处理结果可追溯。

---

## 6. 非功能需求

- 后台运行不抢占前台焦点；
- Chrome 最小化仍可采集，但无法保证零资源占用；
- 任务卡住/风控可见、可暂停、可人工介入；
- API Key、简历、岗位数据本地存储，不上传；
- 日报日志保留 2 周；
- 任务日志/采集统计可供后续分析；
- 安装包不包含 Chrome；
- 单机单用户，最多 3 角色。

---

## 7. 验收标准（摘要）

1. 关闭软件再打开，未完成任务能恢复；
2. 11 号采集、12 号入库的岗位显示 11 号；
3. 采集窗口/12:30/R-2h/R-1h 规则按配置执行；
4. 6 个子任务独立状态，失败可重试，最多 3 次；
5. 角色首次启动后不可修改；复制可用；
6. 同一岗位对不同角色有不同评分；
7. 关闭岗位重新开放后进入待评分；
8. 登录失效/风控/卡住有通知；
9. Excel 链接可点；
10. AI 供应商按排序降级，全部失败走兜底；
11. 飞书日报按角色发送，日志保留 2 周；
12. 任务完成/关闭后 Chrome 关闭。

## 8. 待确认（不影响开工，但影响细节）

- 角色相似度阈值/算法（高重合允许仍然确认，已确认）；
- 子任务重试“5/1/1”的具体含义（5 分钟/1 分钟/1 分钟，还是 5 次/1 次/1 次）；
- 角色软删除后是否占 3 个名额；
- Excel 是否需要“每角色一个 sheet”（默认按所选角色导出）；
- 多账号扩展位是否保留（当前每平台 1 个账号）。
