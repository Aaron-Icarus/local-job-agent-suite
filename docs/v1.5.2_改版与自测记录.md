## 岗位评分链路（v1.5.2 修复）

评分顺序调整为 **AI 优先、规则兜底**：

```text
岗位事实 + 角色画像 + 目标岗位 + 角色关键词
→ 读取 skills/job_scoring_skill.md
→ 调用已启用 AI Provider
→ AI 直接返回 0–100 最终分、理由、风险、结论
→ 保存 score_version = v1.5.3-ai-first
```

- 不再限制 AI 只能在本地分上 ±8 分；AI 分数优先保存。
- AI 不可用、密钥缺失、HTTP 失败、超时、返回空/非法 JSON、缺少有效 score 时，才回退本地规则分，保存 `v1.5-local-fit`。
- AI 不得改写岗位事实/薪资/城市/关闭/重复等硬条件，不得编造简历或岗位经历。
- 角色卡片新增“重新评分”，会标记全量岗位并调用 AI。
- 当前测试：100 个岗位全部 AI 评分成功，provider 为已配置的 Doubao 模型。

关键词链路保持不变：

```text
画像 + 目标 + 城市/薪资 + 历史关键词执行效果
→ daily_keyword_skill.md
→ AI Provider
→ 推荐词 + 兜底词
```

AI 失败时才使用本地关键词和兜底词。

## 飞书机器人配置逻辑（v1.5.2）

### 当前实现：单机器人、多群

当前版本只支持 **1 个飞书自建应用/机器人**，但允许该机器人加入多个飞书群：

```text
1 个 App ID / App Secret
  ├─ 群 A（Chat ID）
  ├─ 群 B（Chat ID）
  └─ 最多 10 个群
```

相关数据：

```text
消息平台/.env
├─ FEISHU_APP_ID
└─ FEISHU_APP_SECRET

feishu_groups
├─ id
├─ name
├─ chat_id
├─ webhook
├─ enabled
├─ is_default
└─ reply_role_uuid

feishu_group_roles
├─ group_id
├─ role_uuid
├─ notify_login
├─ notify_error
└─ notify_daily
```

关键限制：

- `feishu_groups` 没有 `bot_id` 字段；
- App ID/Secret 是全局唯一一份；
- 所有群默认属于同一个机器人；
- `MAX_GROUPS = 10`；
- 消息平台只启动一个飞书长连接进程；
- `channels.config.json` 里的多个 channel 是消息来源/群，不是多个机器人。

### 三个动作的职责

```text
App ID / App Secret
→ 机器人应用身份，用于发送消息、测试群、调用 Open API

群 Chat ID
→ 指定消息发到哪个群

启动消息平台
→ 建立飞书长连接，接收群消息和 @机器人 事件
```

准确关系：

- 添加群只要求群 Chat ID，不要求先启动长连接；
- 测试群要求 App ID/Secret 正确，测试消息走 Open API；
- @机器人、接收群消息要求启动消息平台；
- “同步群到消息平台”只是把本地已保存的群写入消息平台配置，不会自动发现飞书里的新群。

### 顶部群 ID 与群列表的合并

旧版本有两个入口：

```text
顶部群 ID
→ 写入 .env 的 FEISHU_CHAT_ID

添加群
→ 写入 feishu_groups 表
```

两者可能重复或不一致。v1.5.2 已调整：

- 顶部字段改为“默认群 ID（可选）”；
- 保存应用配置时，如果填了群 Chat ID，自动加入群列表；
- 按 Chat ID 去重，同一个群不会重复创建；
- 默认群只用于默认通知/首个群，不改变“单机器人”模型。

当前“测试”按钮发送的是文本消息，不是飞书交互卡片；卡片模板需要单独接入 Card API。

### 如果要支持多个机器人

当前**不实现**多机器人，因为一个机器人加入多个群已经能满足现有场景。若后续要支持，应按下面模型改造，不能只改 UI：

1. 新增机器人表：

```text
feishu_bots
├─ id
├─ name
├─ app_id
├─ app_secret_encrypted
├─ enabled
└─ created_at
```

2. 群表增加机器人归属：

```text
feishu_groups.bot_id
```

3. 增加唯一约束：

```text
(bot_id, chat_id)
```

4. 消息平台按机器人启动多个长连接：

```text
bot A → 长连接 A → 群 A/B
bot B → 长连接 B → 群 C
```

5. 发送层按群所属机器人取 App ID/Secret，不再使用全局 `.env`。

6. UI 改为：

```text
机器人管理：新增/编辑多个机器人
群管理：添加群时选择“所属机器人”
群卡片：显示“机器人 + 群”
默认群：绑定机器人
```

7. 迁移旧数据：

```text
当前 .env 的 App ID/Secret → 默认机器人
已有群 → 全部绑定默认机器人
```

8. 多机器人需要额外处理：

- App Secret 加密；
- 多个长连接的进程/重连/日志隔离；
- 入站事件按 App/机器人路由；
- 群归属校验，避免发错机器人；
- 每个机器人的限流、测试和错误状态。

当前版本维持单机器人；上述方案只作为后续演进设计记录。
