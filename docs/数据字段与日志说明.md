# 数据字段、日志与历史岗位确认说明

## 1. 本地日志

- 目录：`招聘智能体/recruitment-agent/data/logs/`
- 当前文件：`app.log`
- 轮转文件：`app.log.1`、`app.log.2`
- 默认总上限：**5 MB**（可用 `V14_LOG_MAX_BYTES` 覆盖）
- 单文件上限：约 5 MB / 3 = 1.66 MB
- 超过后自动轮转，最多保留 3 个文件，避免无限增长
- 每行一条 JSON：

```json
{"time":"2026-11-07T17:30:00.000Z","level":"info","action":"http","message":"POST /api/jobs/recheck","data":{"status":200,"durationMs":1200}}
```

字段：

| 字段 | 含义 |
| --- | --- |
| `time` | ISO 时间 |
| `level` | `info` / `warn` / `error` |
| `action` | 操作类型，如 `http`、`job_recheck` |
| `message` | 简短说明 |
| `data` | 附加数据：状态码、耗时、数量、错误等 |

查看：

- 客户端“设置 → 本地运行日志”
- 或 `GET /api/logs?limit=200`

## 2. 历史岗位确认

### 触发与中断

职位库右上角“历史岗位确认”按钮。

### 筛选逻辑

```text
未关闭
且 last_seen_date 至少 7 天前
且 last_recheck_at 为空 或 超过 24 小时
按 last_seen_date 从远到近
每次最多 10 个（API 可调）
```

目的：

- 只检查“很久没见但还没关闭”的岗位；
- 避免短时间内反复刷同一个岗位；
- 每次按钮触发都写一条批次记录。再次点击按钮会取消当前批次，界面立即隐藏进度数字。

### 岗位字段

| 字段 | 含义 |
| --- | --- |
| `last_recheck_at` | 该岗位最后一次被“历史岗位确认”检查的时间（总刷时间） |
| `job_status` | `open` / `closed` / `unknown` |
| `status_updated_at` | 状态最后变化时间 |
| `closed_at` | 关闭时间 |
| `last_seen_at` / `last_seen_date` | 最后一次在采集结果中看到 |

### 批次表 `job_recheck_batches`

| 字段 | 含义 |
| --- | --- |
| `id` | 批次号 |
| `started_at` | 按钮触发时间 |
| `finished_at` | 完成时间 |
| `status` | `running` / `finished` |
| `checked_count` | 本轮检查数量 |
| `closed_count` | 本轮确认关闭数量 |
| `skipped_count` | 无法确认/跳过数量 |
| `error` | 批次错误（如有） |

### 确认规则

- 页面 404/410，或页面出现“职位已关闭 / 已下线 / 停止招聘 / 职位不存在”等标记 → 标记 `closed`；
- 页面可访问但没有关闭标记 → 记为 `unknown`（不强行关闭，避免误判）；
- 网络失败/403/429 → `unknown`，不关闭；
- 每个被检查岗位都更新 `last_recheck_at`，即使结果是 unknown；
- 24 小时内重复点按钮，已检查岗位会被筛选掉。

## 3. 其他关键字段

### 岗位 `jobs`

| 字段 | 含义 |
| --- | --- |
| `job_uuid` | 内部唯一 ID |
| `display_id` | 页面展示编号，如 A001 |
| `platform` | BOSS / 猎聘 |
| `platform_job_id` | 平台原始 ID |
| `content_hash` | 内容指纹，用于去重 |
| `first_seen_at` | 首次采集时间 |
| `last_seen_at` | 最后采集时间 |
| `first_seen_date` / `last_seen_date` | 日期版，用于筛选 |
| `ingested_at` | 入库时间 |
| `job_status` | open / closed / unknown |
| `duplicate_status` | unique / duplicate |
| `long_lived_days` | 岗位长寿天数 |
| `facts_json` | 原始事实快照 |

### 角色 `roles`

| 字段 | 含义 |
| --- | --- |
| `role_uuid` / `role_number` | 角色内部/展示 ID |
| `profile_md` | 角色画像 |
| `target_roles` / `target_city` / `target_salary` | 目标条件 |
| `role_keywords_json` | 每日采集关键词 |
| `role_channels_json` | BOSS/猎聘 |
| `status` | pending_confirm / pending_start / running / paused |

### 飞书

| 表/字段 | 含义 |
| --- | --- |
| `feishu_groups.chat_id` | 群 Chat ID（`oc_...`） |
| `feishu_groups.is_default` | 是否默认通知群 |
| `feishu_groups.reply_role_uuid` | 群内 @机器人 使用哪个角色回复 |
| `feishu_group_roles` | 群 × 角色 × 登录/异常/日报节点 |

## 4. 配置项

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| `recheck_min_age_days` | 7 | 最少多少天没见才检查 |
| `recheck_interval_hours` | 24 | 同一岗位最短复查间隔 |
| `V14_LOG_MAX_BYTES` | 5242880 | 日志总大小上限 |

可以在 `settings` 中写入 `recheck_min_age_days`、`recheck_interval_hours` 调整阈值。

## 5. 其他主要表

| 表 | 关键字段 | 含义 |
| --- | --- | --- |

| `collection_events` | `event_date`、`force_reason`、`status` | 一次采集事件 |
| `collection_subtasks` | `platform`、`role_uuid`、`keyword`、`status` | 平台 × 角色 × 关键词子任务 |
| `keyword_tasks` | `subtask_id`、`keyword`、`priority` | 具体关键词采集 |
| `resumes` | `name`、`raw_md`、`parsed_json`、`content_hash` | 简历原文与解析结果 |
| `role_jobs` | `role_uuid`、`job_uuid`、`score`、`tier`、`needs_score` | 角色维度的岗位评分 |
| `reports` | `report_date`、`role_uuid`、`status`、`content`、`sent_at` | 日报草稿/发送记录 |
| `notifications` | `type`、`title`、`body`、`status`、`channels_json` | 通知与本地回退记录 |
| `ai_providers` | `base_url`、`model`、`api_key_encrypted`、`last_status` | AI 供应商与测试状态 |
| `chat_sessions` | `external_key`、`role_uuid`、`state_json` | 对话会话（可绑定飞书群） |
| `chat_messages` | `role`、`content`、`metadata_json` | 对话消息与工具步骤 |
| `settings` | `key`、`value_json` | 采集/日报/登录/复查阈值等设置 |
| `meta` | `key`、`value` | 数据库版本等内部元数据 |

## 6. 清理演示数据

```powershell
cd 招聘智能体\recruitment-agent
npm run v14:clear-demo
```

会先备份 `data/v1.4/jobs.db`，然后清空岗位、角色、评分、简历、日报、任务、通知、对话等业务数据；保留设置、AI Provider、飞书群配置。
