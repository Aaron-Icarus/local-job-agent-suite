# 快捷启动使用说明

这个目录是分享包的“入口层”，面向电脑小白和新对话 AI。

## 目录结构

```text
快捷启动/
  随项目必须的安装包/   可选便携运行环境；准备脚本可下载 Node.js，并缓存 pnpm/飞书 SDK 依赖
  快捷启动脚本/         CMD + PowerShell 双入口
  页面UI/               本地 HTML 控制台
  SKILL.md              给 AI 快速接手项目用的说明
  使用说明.md           给人看的说明
```

## 最推荐入口

第一次换电脑使用，先双击：

```text
快捷启动/快捷启动脚本/准备运行环境.cmd
```

它会先检查本机是否已有 Node.js 20+ 和 pnpm，再让你选择使用本机环境，或准备随包便携环境。

双击后会出现菜单：

1. 如果本机已有 Node.js 20+ 和 pnpm，推荐使用本机环境，只把飞书 SDK 依赖安装到快捷启动依赖区。
2. 如果本机没有合格 Node/pnpm，推荐准备随包 Node.js + pnpm + 飞书 SDK 依赖，不修改系统 PATH。
3. 准备随包依赖，并把随包 Node 注册到当前用户 PATH。
4. 只查看状态，不安装。

说明：默认不偷偷修改本机 PATH。常用快捷脚本会优先使用本机 Node.js 20+；本机没有或版本过低时才使用随包 Node。只有你想在任意 CMD/PowerShell 里直接输入随包 `node` / `pnpm` 时，才需要选择注册用户 PATH。

双击：

```text
快捷启动/快捷启动脚本/启动控制台.cmd
```

如果需要在命令行运行，不要复制相对路径。请优先打开 `页面UI/index.html`，页面会按当前安装位置生成可直接粘贴到 CMD 或 PowerShell 的完整命令。静态模板如下：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "Set-Location -LiteralPath '<分享包实际安装目录>'; & '.\快捷启动\快捷启动脚本\start_dashboard.ps1'"
```

它会打开本地 HTML 控制台，并启动本地 helper，让页面按钮可以用 Windows 文件管理器打开白名单目录。

## 常用脚本

- `准备运行环境.cmd`：先检查本机 Node/pnpm；本机可用时可只安装/修复飞书 SDK 依赖，本机不可用时再下载/准备随包 Node.js，并通过 corepack 准备 pnpm。
- `查看运行环境状态.cmd`：只查看 Node、pnpm、飞书 SDK、Chrome、可选 AI 依赖状态，不安装。
- `注册随包Node到用户Path.cmd`：把随包 Node 注册到当前 Windows 用户 PATH；这是可选动作，需要重新打开终端后生效。
- `首次配置检查.cmd`：检查 Node、Chrome、两个项目目录、示例配置和招聘 Agent preflight。
- `打开BOSS登录.cmd`：打开 BOSS 可见登录/安全验证页。
- `打开猎聘登录.cmd`：打开猎聘可见登录/安全验证页。
- `运行草稿测试.cmd`：调用招聘 Agent 草稿模式。
- `运行定时流程.cmd`：调用招聘 Agent 定时入口，由程序判断当前是否需要采集/日报。

每个 `.cmd` 都有对应 `.ps1`，CMD 面向双击用户，PowerShell 面向 AI 或高级用户。

## 页面里的“复制命令”怎么用

页面里显示的“复制命令”会自动识别当前安装位置，生成类似下面的完整一行命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "Set-Location -LiteralPath '<分享包实际安装目录>'; & '.\快捷启动\快捷启动脚本\prepare_runtime_menu.ps1'"
```

这类命令是给 CMD/PowerShell 使用的，不是文件管理器地址。HTML 页面里会把 `<分享包实际安装目录>` 自动替换成真实目录；静态文档里不会写死某台电脑的 D 盘路径。

如果你把命令粘贴到 Windows 文件管理器地址栏，尤其是在“主文件夹/快速访问”里，Windows 可能会把它当搜索、网页或未知路径处理，看起来就像跳到了浏览器。文件管理器地址栏只适合输入文件夹路径，不会执行命令。

另外，页面里的青色“文件管理器打开...”按钮不是普通链接。它需要本地 helper 才能调起 Windows 文件管理器：

- 如果你直接打开 `页面UI/index.html`，普通链接可能能跳，但青色文件夹按钮会提示 helper 未启动。
- 请双击 `快捷启动\快捷启动脚本\启动控制台.cmd` 打开页面；这个脚本会同时启动 helper。

正确方式：

1. 小白用户：在文件管理器里打开 `快捷启动\快捷启动脚本`，直接双击 `.cmd` 文件。
2. 命令行用户：从 HTML 控制台复制完整命令；它会自动进入分享包根目录再执行脚本，不依赖当前终端目录。
3. 如果已启动本地控制台 helper，可以点击页面里的“文件管理器打开脚本目录”按钮。

## 安装包目录

GitHub/source 版本默认不提交 Node.js 二进制和 pnpm 缓存，避免仓库过大。如果本机没有 Node.js 20+，推荐运行：

```text
快捷启动/快捷启动脚本/准备运行环境.cmd
```

它会把便携版 Node.js 放在：

```text
快捷启动/随项目必须的安装包/node/node.exe
```

快捷启动脚本会优先使用系统 PATH 中合格的 Node.js 20+；如果本机没有或版本过低，再使用这个随包 Node。

如果确认使用者电脑已经有合格的本机 Node.js/pnpm，且不需要离线交付，可以删除 `随项目必须的安装包/` 下面准备脚本生成的大目录，例如 `node/`、`corepack/`、`pnpm-store/`、`message-platform-vendor/` 和 `_downloads/`；保留 `README.md` 即可。

Chrome 建议正常安装到系统，或者在招聘 Agent `.env` 中配置 `CHROME_PATH`。
